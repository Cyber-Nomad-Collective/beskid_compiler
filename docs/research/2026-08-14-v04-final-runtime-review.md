# v0.4 Final Canonical Runtime Review

Date: 2026-08-14

## Scope and method

Read-only review of the current canonical runtime delta in `compiler`, using `origin/main` as the pre-change baseline and including committed plus working-tree changes. Reviewed:

- `runtime_manifest.bsol` and checked-in generated ABI artifacts
- lifecycle and composition
- GC allocation, marking, roots/handles, sweep, and collection
- scheduler state, queues, context-switch boundary, cleanup, and public handles
- process, filesystem, and byte-I/O wrappers
- canonical-runtime authorization and retirement changes
- `runtime/beskid/tests/runtime_semantics`

No runtime source was edited. No Cargo, build, linker, or test command was run, per request. `git diff --check origin/main` was clean. GitNexus was stale, so it was not used as correctness evidence.

## Verdict

**Not releasable.** The diff has multiple P0 ABI contradictions between the sole-source manifest, stale generated artifacts, and the canonical Beskid implementation. The scheduler cannot be shut down, its tests necessarily hit lifecycle traps, the declared runtime tests omit GC entirely, and composition is still mostly a deliberately disabled shell.

| Severity | Count | Summary |
|---|---:|---|
| P0 | 8 | manifest/generated/runtime ABI split; lifecycle/TLS mismatch; scheduler record collision; missing trampoline export; no scheduler teardown; composition contract not implemented; target-invalid read adapter; tests do not exercise the claimed runtime |
| P1 | 7 | alignment/free-list failure; unchecked GC accounting; unsafe root-chain trust; bounded marker fails with seven roots; dropped scheduler queue failures; incomplete fiber result/argument semantics; adapter implementation evidence absent |
| P2 | 4 | misleading names/comments, weak source-text tests, silent root-registration capacity failure, incomplete negative-state tests |

## P0 findings

### P0-1 — The generated ABI is stale relative to the sole-source manifest

**Evidence**

- `runtime_manifest.bsol:1-10` declares schema 2 and build profiles.
- `runtime_manifest.bsol:96-107` declares `fs_read_text(pointer path, pointer text_out) -> i32`.
- `runtime_manifest.bsol:244-265` declares the new lifecycle, TLS, heap, fiber, scheduler, and composition layouts.
- Checked-in `crates/beskid_abi/include/abi-v5.json` still declares schema 1, `fs_read_text(pointer) -> pointer`, 32-byte `BeskidTlsState`, the corruption cookie, and no new heap/scheduler/composition layouts (`abi-v5.json:413-423`, `949-1028`).
- `crates/beskid_abi/src/generated/abi_v5_contract.rs` likewise embeds schema 1 and the old signatures/layouts.

This defeats `runtime_manifest.bsol:1-2` (“sole source of truth”). Code generation, authorization, linkage, and consumers can each observe different contracts.

**Exact fix**

Regenerate every manifest-derived artifact from the schema-2 manifest in one atomic change, including ABI JSON, Rust contract/constants, headers, assembly includes, capability maps, status/layout projections, export allowlists, and provenance hashes. Add a freshness gate that compares regenerated bytes with the checked-in tree and fails on any drift.

### P0-2 — Lifecycle implements the retired 32-byte TLS/cookie layout, not the manifest lifecycle state machine

**Evidence**

- Manifest: `BeskidRuntimeState[56..60] = lifecycle_state`, `[60..64] = lifecycle_generation`; `BeskidTlsState` is 48 bytes with composition fields (`runtime_manifest.bsol:244-247`).
- Runtime: `Lifecycle.bd:9-14` fixes TLS size at 32; `Lifecycle.bd:20-21` says offset 56 is a corruption cookie; `Lifecycle.bd:23-35` only stamps ABI version; `Lifecycle.bd:76-100` allocates/frees 32 bytes.
- Runtime does not perform `Uninitialized -> Initializing -> Active -> ShuttingDown -> ShutDown` transitions from `runtime_manifest.bsol:169` and never increments lifecycle generation.

A caller compiled from the manifest can read/write fields that the runtime never allocated or transitioned. Composition scope fields at TLS offsets 32 and 40 are out of bounds in the implementation.

**Exact fix**

Make generated accessors the only layout authority. Allocate exactly 48 bytes. Implement the declared lifecycle state transitions at offsets 56/60, including rollback on failed attach/init and generation advance on successful reinitialization. Preserve no retired cookie semantics. Initialize and validate TLS `reserved`, `composition_scope`, and `composition_depth`. Add transition-table tests for every legal and illegal edge.

### P0-3 — Fiber offset 120 and scheduler size conflict with the manifest

**Evidence**

- Manifest assigns fiber offset 120 to `stack_usable_size` (`runtime_manifest.bsol:259`).
- Runtime assigns offset 120 to `generation` and uses it for existence/handle validity (`Scheduler/Core.bd:70-75`, `110-171`).
- Manifest freezes scheduler size at 3504, ending with `scheduler_context` at 3496 (`runtime_manifest.bsol:260-263`).
- Runtime adds `scheduler_context_size` at 3504 and allocates 3512 bytes (`Scheduler/Core.bd:84-88`, `392-408`).
- Cleanup always frees a stack using the constant 65536 rather than a manifest-owned per-record usable size (`Scheduler/Core.bd:338-349`).

This is direct ABI field aliasing. A generated accessor sees a generation as a stack size, and a manifest-sized scheduler allocation would be overrun at 3504.

**Exact fix**

Choose and encode one manifest layout. Prefer retaining `stack_usable_size` at 120, because `guarded_stack_free` requires the exact usable size. Put generation in a newly declared field by expanding `BeskidFiberRecord` and recalculating every downstream scheduler offset/size, or add a manifest-declared parallel generation array. Remove `scheduler_context_size` or declare it and increase manifest size. Generate all offsets; do not duplicate literals in Beskid source. Cleanup must free the recorded stack size.

### P0-4 — The manifest-required return trampoline export is absent and has the wrong source signature

**Evidence**

- Manifest requires export `beskid_rt_v5_fiber_return_trampoline() -> never` and an intrinsic with the same symbol (`runtime_manifest.bsol:63`, `86`).
- Runtime defines only `pub unit FiberReturnTrampoline()` with no `[Export]` annotation (`Scheduler/Core.bd:380-389`).
- `FiberAlloc` passes the local function pointer directly to `ContextInit` (`Scheduler/Core.bd:199`).

The exact export/authorization contract is not satisfied; runtime-kit export auditing/linkage can reject or omit the trampoline.

**Exact fix**

Define `[Export(Abi:"C", Symbol:"beskid_rt_v5_fiber_return_trampoline")] pub never FiberReturnTrampoline()`, preserve the terminal trap after switching back, and pass the manifest-authorized trampoline symbol consistently. Add an exact-symbol/signature test and a target execution test for entry return on all three ABIs.

### P0-5 — Scheduler ownership has no teardown path, making process shutdown impossible after initialization

**Evidence**

- `SchedInit` allocates the scheduler table and scheduler context and publishes `RuntimeState.scheduler` (`Scheduler/Core.bd:392-410`).
- No `SchedShutdown`/equivalent exists; storage tables also allocate process-owned memory.
- `ProcessShutdown` traps while `runtime.scheduler != 0` (`Lifecycle.bd:37-62`).
- Both scheduler tests initialize a scheduler then detach and call `ProcessShutdown` without clearing/freeing it (`SchedulerTests.bd:6-27`, `29-45`).

The runtime leaks scheduler context/table, guarded stacks, cancel slots, and optional channel/mutex/waitgroup/hub tables, and cannot legally shut down.

**Exact fix**

Add manifest-authorized scheduler shutdown/ownership semantics. Stop accepting work, require no running context, drain or reject pending work, clean every fiber exactly once, free auxiliary tables, free scheduler context and scheduler table with exact sizes, clear `RuntimeState.scheduler`, then allow lifecycle shutdown. Make teardown idempotence/illegal-order behavior explicit and test success plus active-fiber rejection.

### P0-6 — Composition does not implement its manifest state/layout contract

**Evidence**

- Manifest statuses are Configuring=1, Activating=2, Active=3, ShuttingDown=4, ShutDown=5 (`runtime_manifest.bsol:170`) and declares registration/plural/activation/scope fields (`runtime_manifest.bsol:264-265`).
- Runtime uses Active=2 and ShutDown=3 (`Composition.bd:4-8`).
- `CompositionRegister` always returns false; both resolve functions always return null; bind/scope enter/scope leave trap; scope depth always returns zero. Launch activates an empty shell, and shutdown performs no disposal.

This is not merely fail-closed optional behavior: the manifest explicitly declares state and ownership structures that the implementation ignores or reinterprets.

**Exact fix**

Either remove the unimplemented composition capability/layout/status surface from the canonical v0.4 manifest, or fully implement it. For implementation: use generated status values, store only rooted/authorized compiler-planned registrations, perform Configuring→Activating→Active with rollback, implement fiber/TLS scope ownership in the 48-byte TLS contract, dispose in reverse activation order, enforce open-scope count, then transition Active→ShuttingDown→ShutDown. Do not retain managed pointers without root handles.

### P0-7 — `syscall_read` is not a cross-target authorized adapter

**Evidence**

- `Syscalls.bd:14-17` directly calls `read(fd, buffer, len)`.
- Manifest declares POSIX `read` only for Linux and Darwin (`runtime_manifest.bsol:281`, `310`). Windows declares `ReadFile` with a different signature (`runtime_manifest.bsol:353`).
- There is no manifest intrinsic named `read` that abstracts the target split; `context_*` are explicitly intrinsic-authorized, but byte read is not.

The canonical source cannot have the same authorized lowering/linkage on Windows.

**Exact fix**

Declare a target-neutral byte-read intrinsic with signed partial-transfer semantics, bind it to POSIX `read` on Unix and a Windows adapter around `ReadFile`, and call that intrinsic from `SyscallRead`. Alternatively split target-specific canonical sources under manifest ownership. Add per-target signature and negative-error tests.

### P0-8 — The new runtime tests do not constitute executable coverage of the claimed behavior

**Evidence**

- `runtime_semantics.bproj:12-25` declares targets for lifecycle, composition, and scheduler only; `GcTests.bd` is omitted.
- Scheduler tests necessarily violate the new shutdown precondition (P0-5).
- Scheduler tests allocate entry address `1` but never execute a context switch, so ABI entry, stack alignment, argument passing, yield/resume, return trampoline, and cleanup are untested (`SchedulerTests.bd:18`, `31`).
- No I/O/process target exists.

**Exact fix**

Add `GcTests` and I/O/process test targets. Give each test a complete teardown path. Add executable scheduler tests using real entry functions and checking argument register delivery, repeated yield/resume, return trampoline, cancellation, detached cleanup, stale handles, and stack/context freeing. Add target-matrix tests or assembly harnesses for all supported ABIs.

## P1 findings

### P1-1 — Valid high-alignment allocations can fail with available space

`GcAlloc` states that an alignment gap cannot be smaller than 16, but an 8-aligned bump aligned to 16 can have an 8-byte gap (`Allocation.bd:93-99`). The function returns null after collection despite sufficient contiguous space. Free-list reuse also only accepts blocks whose start already has the requested alignment (`Allocation.bd:35-46`).

**Exact fix:** absorb a sub-header prefix into the allocated object/padding with accounting based on the consumed block, or split only when prefix and suffix are each zero or at least 16 bytes. Support aligned placement inside free blocks and correctly rewrite prefix/suffix headers. Add 16/32/64-byte alignment tests from every 8-byte residue and tiny-remainder cases.

### P1-2 — GC accounting arithmetic can wrap

Allocation increments `live_bytes`/`live_count` without overflow checks (`Allocation.bd:68-72`, `104-106`), and sweep accumulates block sizes similarly. Wrapped counters can suppress collection and falsify state.

**Exact fix:** checked-add before publication; on overflow trap as runtime corruption or fail allocation without mutation. Test near-maximum synthetic state.

### P1-3 — Root-frame traversal trusts arbitrary/cyclic native structures

`MarkRoots` follows `frame.previous`, `frame.slots`, and `slot_count` with no ownership, bound, cycle, or maximum-depth validation (`RootsHandles.bd:120-134`). A malformed frame can loop forever or dereference arbitrary memory. External roots similarly dereference registered addresses directly (`RootsHandles.bd:136-145`).

**Exact fix:** make push/pop helpers the sole frame publication API, validate TLS ownership and previous-chain discipline, bound frame depth/slot count, and detect cycles. For external roots, use runtime-owned root cells or an authenticated registration record rather than retaining arbitrary addresses without lifetime proof.

### P1-4 — Six gray slots make ordinary root sets fail collection

The manifest deliberately allocates six gray entries (`runtime_manifest.bsol:254`). Seven distinct simultaneous roots set the failed sentinel. Collection then retains all garbage and future allocation can fail despite reclaimable space. This is fail-closed for memory safety but not a viable collector.

**Exact fix:** use an adequately sized or growable runtime-owned mark stack, or implement bounded pointer-reversal/overflow rescanning. Preserve the no-sweep-on-incomplete-mark invariant. Add breadth tests well above six roots and children.

### P1-5 — Queue capacity failures are silently discarded

`RunQueuePush` returns false when full, but `SchedulerSpawn`, wake application, and yield do not propagate or trap on failure. A newly allocated runnable fiber can become permanently unreachable from the queue; a yielding running fiber can be lost.

**Exact fix:** make enqueue failure transactional. Spawn must clean/reject the new fiber; wake/yield must retain state and report a deterministic capacity error or provision queue capacity from the maximum fiber count. Since only 16 fibers exist, size and prove the queue so legal state cannot overflow.

### P1-6 — Fiber result and public spawn argument semantics are incomplete

`FiberReturnTrampoline` always records result `0` (`Scheduler/Core.bd:382-388`), so nonzero entry returns are lost unless the ABI explicitly requires void entries. Separately, `FiberSpawn(pointer entry, pointer argument)` allocates a cancel slot but calls `SchedulerSpawn(entry, null, cancelSlot)`, dropping `argument` (`Fiber/Fiber.bd:5-12`).

**Exact fix:** freeze the entry signature in the manifest and assembly contract. If entries return `i64`, preserve the ABI return register into the trampoline/outcome; if void, remove misleading join-value semantics for this path. Pass `argument` as the environment/argument. Add exact non-null argument and nonzero result tests.

### P1-7 — Manifest filesystem target bindings exist, but implementation evidence is absent from the reviewed runtime

The manifest names `beskid_rt_v5_{linux,darwin,windows}_fs_*` implementations (`runtime_manifest.bsol:96-155`), while `Process.bd` only calls intrinsics. No runtime semantic tests exercise status translation, output ownership, partial reads/writes, UTF conversion, handle closure, or allocation failure.

**Exact fix:** ensure each named implementation is generated/linked and provenance-authorized for only its declared imports. Add fault-injection tests for every `BeskidFsStatus`, zero-length files, partial I/O, invalid UTF/path input, allocation failure, and cleanup on each early return.

## P2 findings

### P2-1 — “Free list” is an implicit heap scan

`AllocateFromFreeList` scans every block from heap start to bump; there is no free-list head/link. Rename it to reflect first-fit heap scanning or add a real linked/bin free list. This matters for understanding complexity and corruption invariants.

### P2-2 — Source-text assertions do not validate signatures or authorization

`canonical_runtime_sources.rs` checks string containment for process/I/O wrappers. Such tests accepted a stale generated ABI and cannot prove type checking, capability authorization, target binding, or linkage.

**Exact fix:** compare parsed/lowered function signatures against manifest intrinsics and inspect resolved capability/import edges; retain string tests only for smoke coverage.

### P2-3 — Root registration capacity failure is silent

`GcRegisterRoot` returns `unit` and silently ignores the 64th root. Callers such as fiber allocation cannot know their environment was left unrooted.

**Exact fix:** return `bool`/status, or trap before publishing an object that requires a root. Make duplicate registration success explicit.

### P2-4 — Negative transition and corruption tests are missing

There are no executable tests for wrong-thread detach, detach with roots/current fiber, shutdown with heap/callback/scheduler/root active, composition trap edges, malformed free blocks/descriptors, gray overflow recovery, queue-full behavior, or double cleanup.

**Exact fix:** add trap-aware subprocess tests for every illegal lifecycle/state transition and corruption sentinel, plus post-failure invariants proving no partial publication or double free.

## Offset and signature audit summary

### Correct within the manifest

- Heap layout arithmetic is internally contiguous: gray count 64, six entries 72–119, external count 120, 63 roots 128–631, handle count 632, eight 16-byte handles 640–767; total 768 (`runtime_manifest.bsol:254-255`).
- Runtime heap constants match those offsets.
- Object header and type descriptor field offsets used by GC match the manifest (`runtime_manifest.bsol:241`, `248`).
- Context assembly signatures and target register-location declarations are coherent at the manifest boundary (`runtime_manifest.bsol:360-378`), and `Context.bd:29-37` forwards the same parameter order.
- POSIX write/read return types are signed `isize`; widening to `i64` preserves negative errors and partial counts on supported 64-bit targets.

### Incorrect or unproven

- Generated ABI vs manifest: stale.
- Runtime/TLS lifecycle layouts: incorrect.
- Composition status values: incorrect.
- Fiber offset 120: incorrect.
- Scheduler total size: incorrect.
- Trampoline export/signature: incorrect.
- Windows syscall read authorization: incorrect.
- Context switch behavior from Beskid scheduler: untested.
- Stack-top ABI alignment/shadow-space behavior in integrated scheduler: untested.
- Scheduler and auxiliary-table cleanup: absent.

3. Reconcile lifecycle/TLS, fiber, scheduler, and composition layouts before any behavioral work.
4. Implement scheduler shutdown and exact resource ownership.
5. Repair target-neutral I/O authorization and provide all named adapters.
6. Fix aligned free-block splitting and root/mark-stack safety.
